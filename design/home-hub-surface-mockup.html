What this mockup shows (and decides)

It pictures the shell, not a domain. Every frame maps to a PRD 01 P0: the canonical grid + header (P0-1/2/3/4), the Assistant Bar's three states (P0-6), generic tap-to-focus with one way back (P0-7), and the ambient⇄engaged mode takeover (P0-8). Tile empty/error states are not re-drawn — they live in shopping-surface-mockup.html; duplicating them would drift the two apart.

Engaged mode = the same feature as the resting bar, expanded. Tapping the stubbed bar is the Phase-0 synthetic trigger (P0-8 / critic C2); the real hot-word + silence/close-out voice events (Phase 5) plug into the same state machine without a layout rebuild. The conversation is text-first (Phase 2); the waveform / live-transcription strip is tagged Phase 5 voice so nothing here implies voice ships in Phase 0.

Two engaged-mode open flags surfaced honestly. The reference wireframe (engaged-mode-notes.md) puts a Family Calendar in the sidebar and System Logs in the footer. Calendar isn't one of the three tile domains, so it's shown muted / "pending domain decision" rather than committed; System Logs is drawn as dev-only. Both decisions belong to the Assistant Bar PRD — this mockup flags them, it doesn't settle them.

Every value is a seed token. Header clock is type.hero (52); tile & sidebar numbers are type.number (30) in each domain's accent; surfaces step bg.page → bg.tile → bg.raised (no shadows, seed §5). The "listening" accent reuses accent.tasks as a stand-in — a dedicated listening/waveform token is the one addition the seed anticipates for engaged mode (seed §10 / engaged-notes), added only when the real voice UI needs it. Seed data is mock, shaped like the real files (AGENTS.md).
